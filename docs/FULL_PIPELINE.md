# 전체 실행과 결과 점검

## 1. 사전 조사부터 최종 보고서까지

```bash
uv run python app.py --prepare --as-of 2026-09-30 --pdf
uv run python -m tools.audit_results
```

1. 디렉토리북의 기업 레코드를 읽고 AI 관련성을 45개사 모두 검토한다.
2. AI 관련성 통과 기업의 비상장 여부·최신 투자 단계·Exit 여부를 DART·Tavily로 조사한다.
3. 모든 후보를 순서대로 선택하고 작업 상태와 검색 재시도 횟수를 초기화한다.
4. 요건 미충족은 제외, 확인불가는 보류한다. 적격 기업은 기술 → 시장 → 경쟁 → 투자 판단을 진행한다.
5. 기술·시장 근거가 부족하면 각 단계에서 최대 한 번 재검색한다. 산업 수치를 해당 기업의 실제 성능으로 간주하지 않는다.
6. 채점 근거 ID를 검증하고 3회 채점의 중앙값을 사용한다. 매출·투자 유치와 매출 체크리스트 Q7은 코드로 계산한다.
7. 기업 결과를 즉시 저장하고 다음 기업으로 진행한다. 처음 투자 적격이 나와도 종료하지 않는다.
8. 전체 후보 소진 후 순위를 매긴다. 총점 → 기술력 → 미확인 항목 수 → 실적 순이다.
9. 1위의 보고서를 작성한다. 선정 기업이 없으면 기준 미달·추가 확인 사유 중심의 보고서를 만든다.
10. 점수·평균·판정·순위·인용과 PDF의 5쪽 제한을 재검증한다. 레이아웃과 인용 내용의 의미는 별도 검토가 필요하다.

## 2. 저장과 재개

`outputs/evaluation_results.json`은 기업 결과 저장 직후 갱신한다. `run.complete=false`는 실행 중 또는 중단 상태다. 완료한 기업은 유지하고 미완료 기업은 처음부터 평가한다.

```bash
uv run python app.py --resume --as-of 2026-09-30 --pdf
```

기준일·평가 기준·기업 입력·코드·프롬프트·사전 조사 결과가 같아야 재개할 수 있다. 달라졌다면 `--resume` 없이 새 평가를 실행한다. 재개와 `--prepare`는 함께 사용하지 않는다.

보고서 문장이나 PDF만 수정할 때는 전체 채점을 반복하지 않는다.

```bash
uv run python app.py --report-only --pdf
uv run python -m tools.audit_results
```

보고서 재생성은 저장된 원래 기준일과 점수를 사용한다. 기업·평가 기준 변경을 반영하려면 전체 평가가 필요하다.

채점 규칙만 보완했을 때는 완료한 전체 평가의 기술·시장·경쟁 분석을 유지하고, 점수가 산출됐던 모든 기업을 다시 채점할 수 있다. 3회 실제 채점과 전체 순위·보고서 재생성을 수행한다. 기업 입력이 바뀌었으면 이 방식 대신 전체 분석을 실행한다.

```bash
uv run python app.py --rescore --pdf
uv run python -m tools.audit_results
```

경쟁사 출처·별칭 처리를 수정한 경우 `uv run python app.py --rescore --refresh-competition --pdf`로 점수 산출 기업의 경쟁 분석까지 갱신한다. 기존 경쟁사 웹 근거는 갱신 결과로 교체하며 기업·기술·시장 근거는 유지한다.

개발 성숙도는 기업 원문에 현재 납품·양산이 직접 명시된 경우 해당 단계로 평가한다. 예정·계획·부정 표현은 제외하며 TRL 숫자를 만들어 넣지 않는다. 경력 기간·성능 수치가 빠진 항목은 확인된 정성적 근거 범위에서 평가한다.

## 3. 결과 읽기

- `evaluation_summary.md`: 45개사 판정과 점수 산출 여부.
- `evaluation_results.json`: 보류·제외 사유, 15항목 점수, 회차별 총점 범위, 원문 근거, 오류.
- `validation.json`: `passed=true`, 기업 수, 점수 산출 수, 분석 오류, PDF 페이지 수.
- `report.pdf`: SUMMARY·기업 개요·기술/시장/경쟁·투자 판단·REFERENCE. 미선정일 때는 별도 목차.

`보류`는 투자 요건 미확인, 분석 오류, 총점 미달, 기술력 기준 미달을 구분해서 읽는다. 정보를 확인하지 못했다는 이유만으로 해당 정보가 미공개이거나 실적이 없다고 단정하지 않는다.

## 4. 조사 캐시

G4는 기업 입력·프롬프트·모델이 같은 결과를 재사용한다. G1~G3는 기업 입력 해시와 기준일 대비 14일 유효기간을 검사한다. Tavily 검색도 14일 캐시를 사용한다.

```bash
# 검색 캐시는 재사용하고 외부 판정을 다시 생성
uv run python app.py --prepare --refresh-external --pdf
```

과거 기준일은 당시 웹 상태를 재현하지 않는다. 투자 단계와 Exit 여부는 현재 확보 가능한 출처로 확인한다. 정확한 법인 일치를 찾지 못한 기업은 비상장으로 추정하지 않는다.

## 5. 원문 매출 표 정정

팀의 매출 수정 커밋 `c7878a4`를 개인 저장소에 반영했다. 매출 표의 연도·지역 순서와 빈 매출 표시를 보존하고 K·M 단위를 읽는다. 원화·달러가 병기된 해외 칸은 원문 달러 값을 사용한다. 원화만 적힌 해외 칸에는 임의 환율을 적용하지 않는다.

```bash
# 기존 기업 데이터의 매출만 원문 표와 대조; LLM 호출 없음
uv run python -m rag.parse_revenue_repair
uv run python -m rag.parse_revenue_repair --write
```

표 형태가 지원되지 않으면 기존 추출값을 유지한다. 수정 대상은 C03·C07·C08·C18·C39 다섯 기업이었다. C03의 2024년 국내 매출 21,818천원은 21,818,000원, 약 0.2억 원이다. E2는 확인 가능한 1억 원 미만 매출 2점이며 Q7은 PARTIAL이다. E2의 점수가 같아도 확인불가 표시는 제거한다.

기업 입력이 정정되면 이전 분석을 재채점만 하지 않고 전체 파이프라인을 다시 실행한다. 결과 점검은 Q7과 E2/E3의 점수·확인불가 표시가 기업 숫자와 일치하는지도 확인한다.
